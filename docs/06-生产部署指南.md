# 06 · 生产部署指南

> 适用场景：将「飞书报工系统」正式部署到服务器，供企业内部使用。
> 关联文档：[04-飞书对接方案](./04-飞书对接方案.md)、[05-技术架构与接口清单](./05-技术架构与接口清单.md)

## 一、部署架构

```
┌─────────────────────────────────────────────────────────────┐
│  飞书客户端（工作台 → 打开网页应用）                            │
│     │  HTTPS 访问应用主页 / 事件回调 POST                      │
└─────┼───────────────────────────────────────────────────────┘
      ▼
┌───────────────────────────────────────────────┐
│  Nginx (公网, 443 HTTPS)                        │
│  ├── /            → 前端静态资源 (web/dist)      │
│  ├── /api/*       → 反向代理 Node 后端           │
│  │                   (http://127.0.0.1:3000)    │
│  └── /api/internal/feishu/* → 飞书事件回调       │
└───────────────┬───────────────────────────────┘
                ▼
┌──────────────────────────────┐      ┌─────────────────────┐
│  Node.js (NestJS, PM2 托管)    │      │  MySQL 8.x           │
│  http://127.0.0.1:3000        │ ───► │  库: feishu-work     │
│  定时任务: 审批对账/通讯录同步    │      │  (云数据库或自建)     │
└──────────────────────────────┘      └─────────────────────┘
```

## 二、环境要求

| 项 | 要求 |
|---|---|
| 服务器 | 2C4G 起步，Linux（Ubuntu 20.04+/CentOS 7+）或 Windows Server |
| Node.js | ≥ 18 LTS（建议 20 LTS） |
| MySQL | 8.x，字符集 `utf8mb4` |
| 域名 | 一个可解析的公网域名，需 **HTTPS 证书**（事件回调强制要求 HTTPS） |
| Nginx | 1.20+（或等价网关） |
| 飞书 | 自建应用已创建，权限/事件订阅/发布完成 |

> ⚠️ 事件回调地址、网页应用主页必须为 **公网 HTTPS** 域名，否则飞书无法访问。

## 三、飞书应用正式配置（发布前）

在[飞书开发者后台](https://open.feishu.cn/app)完成：

1. **应用能力** → 添加 **网页应用**，主页地址填 `https://你的域名/`
2. **权限管理** 开通：
   - `contact:user.base:readonly`（通讯录）
   - `contact:department.base:readonly`（部门）
   - `im:message`（发消息）
   - `approval:approval`（审批）
   - 网页应用能力（端内免登取 open_id）
3. **事件订阅** → 添加 `approval_instance` 事件，请求地址填：
   `https://你的域名/api/internal/feishu/approval-callback`
   - 建议开启 **Encrypt Key**（后端需配合解密，见 07 文档）
   - 保存时飞书会发送 URL 校验，后端已实现 `challenge` 应答
4. **版本管理与发布** → 创建版本：
   - 默认能力选 **网页应用**
   - **可用范围**：配置为使用报工系统的员工范围（可用范围外无法登录/收消息）
   - 申请线上发布，等待管理员审核通过

> 审批定义：在飞书「审批」应用后台创建名为「报工审批」的审批定义，把其 `approval_code` 填入后端 `FEISHU_APPROVAL_CODE`。

## 四、后端部署

### 4.1 拉取代码并安装

```bash
cd /opt
git clone <你的仓库地址> feishu-work
cd feishu-work/server

# 安装依赖（生产只装运行时依赖）
npm ci --omit=dev
```

### 4.2 配置环境变量

```bash
cp .env.example .env
vim .env   # 按实际填写，参考下表
```

| 变量 | 说明 | 示例 |
|---|---|---|
| `PORT` | 后端监听端口（Nginx 代理到它） | `3000` |
| `DATABASE_URL` | MySQL 连接串 | `mysql://user:pass@host:3306/feishu-work` |
| `FEISHU_APP_ID` | 飞书应用 AppID | `cli_xxxx` |
| `FEISHU_APP_SECRET` | 飞书应用 AppSecret | `xxxx` |
| `FEISHU_APPROVAL_CODE` | 审批定义编码 | `报工审批` |
| `FEISHU_EVENT_VERIFY_TOKEN` | 事件订阅校验 Token | 飞书后台生成 |
| `FEISHU_EVENT_ENCRYPT_KEY` | 事件订阅加密 Key（可选） | 飞书后台生成 |
| `JWT_SECRET` | **必须更换**为强随机串 | `openssl rand -base64 32` |
| `JWT_EXPIRES_IN` | JWT 有效期 | `7d` |
| `WORKING_HOURS_LIMIT` | 工作日免审批额度 | `8` |

> `JWT_SECRET`、`FEISHU_APP_SECRET` 属敏感信息，务必用强随机值，且不要把 `.env` 提交到仓库（已 gitignore）。

### 4.3 生成 Prisma Client 并同步表结构

```bash
# 方式一（推荐，无需影子库，直接同步现有库）
npx prisma db push

# 方式二（正式迁移历史，生产无需影子库）
npx prisma migrate deploy   # 应用仓库中已生成的 migration
```

> 说明：`prisma migrate dev` 需要在**有权创建影子库**的环境执行（如本地/CI），生成 migration 文件后提交；生产用 `migrate deploy` 应用即可，**不需要**全局建库权限。

### 4.4 构建

```bash
npm run build          # 产出 dist/
```

### 4.5 进程托管（PM2 推荐）

```bash
npm install -g pm2
cd /opt/feishu-work/server

pm2 start dist/main.js --name feishu-work-server --max-memory-restart 500M
pm2 save                # 保存进程列表
pm2 startup             # 开机自启（按提示执行输出的命令）
```

常用 PM2 命令：

```bash
pm2 status                    # 查看状态
pm2 logs feishu-work-server   # 实时日志
pm2 restart feishu-work-server
pm2 monit                     # 资源监控
```

### 4.6 定时任务

后端内置（`@nestjs/schedule`）：

| 任务 | 频率 | 说明 |
|---|---|---|
| 审批对账 | 每 5 分钟 | 主动查询审批中实例状态，防丢事件 |
| 通讯录同步 | 每 6 小时 | 增量同步飞书用户到缓存表 |

PM2 托管下随进程运行，无需额外配置。

## 五、前端构建与部署

```bash
cd /opt/feishu-work/web
npm ci
cp .env.example .env    # 配置 VITE_FEISHU_APP_ID
npm run build           # 产出 dist/，由 Nginx 托管
```

前端 `dist/` 产物为纯静态文件，部署到 Nginx 根目录即可。

## 六、Nginx 配置示例

```nginx
server {
    listen 443 ssl http2;
    server_name feishu-work.example.com;   # 替换为你的域名

    ssl_certificate     /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;

    # 前端静态资源
    root /opt/feishu-work/web/dist;
    index index.html;

    # SPA 路由回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源长缓存
    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # 后端 API + 飞书事件回调 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

# HTTP → HTTPS 跳转
server {
    listen 80;
    server_name feishu-work.example.com;
    return 301 https://$host$request_uri;
}
```

校验与重载：

```bash
nginx -t
systemctl reload nginx
```

## 七、数据库运维

### 7.1 备份（建议每日）

```bash
# 定时任务（crontab）
0 2 * * * mysqldump -u feishu-work -p'***' feishu-work > /backup/feishu-work_$(date +\%F).sql
# 保留最近 7 天
0 3 * * * find /backup -name 'feishu-work_*.sql' -mtime +7 -delete
```

### 7.2 版本升级

1. 拉取新代码 → `npm ci --omit=dev` → `npm run build`
2. 若有 schema 变更：开发环境执行 `npx prisma migrate dev` 生成新 migration → 提交 → 生产执行 `npx prisma migrate deploy`
3. `pm2 restart feishu-work-server` → 前端重新 `npm run build` 覆盖 `dist/`

## 八、安全加固清单

- [ ] 更换 `JWT_SECRET` 为强随机值
- [ ] 后端监听内网（`127.0.0.1:3000`），只经 Nginx 对外
- [ ] 全站 HTTPS；事件回调域名必须 HTTPS
- [ ] 飞书后台开启 **IP 白名单**（可选，限定回调来源）
- [ ] 事件订阅启用 **Encrypt Key**（后端需解密，见 07 文档 6.3）
- [ ] 严格配置应用**可用范围**，避免越权
- [ ] 数据库账号最小权限（业务库 + 可选影子库），不使用 root
- [ ] 定期备份数据库

## 九、日志与监控

| 内容 | 方式 |
|---|---|
| 后端日志 | `pm2 logs feishu-work-server`；NestJS Logger 输出到 stdout |
| 日志轮转 | `pm2 install pm2-logrotate`（按大小/时间切割） |
| 错误告警 | 可对接飞书机器人 webhook，把 `pm2 logs` 过滤出的 error 推送 |
| 进程监控 | `pm2 monit`；可接入 uptime 类探针 |

## 十、上线检查清单

- [ ] 域名解析正常、HTTPS 证书有效
- [ ] Nginx 能访问前端页面、`/api` 代理正常
- [ ] 飞书后台：主页地址、事件订阅地址均为线上 HTTPS 域名
- [ ] 应用已发布，可用范围覆盖目标员工
- [ ] 后端 `.env` 已填真实 AppID/Secret/审批编码/强 JWT_SECRET
- [ ] `npx prisma db push` 或 `migrate deploy` 成功，表结构完整
- [ ] PM2 进程 running，重启后自启
- [ ] 手机端/桌面端飞书工作台打开应用可**免登**进入
- [ ] 提一条工作日 ≤8h 报工（免审批生效）与一条加班报工（走审批）
- [ ] 审批人收到卡片提醒，审批后状态回写并通知报工人
